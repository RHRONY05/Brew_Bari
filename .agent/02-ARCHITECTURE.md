## Routes & rendering
| Route | Who | Rendering | Data |
|---|---|---|---|
| `/` | anyone | RSC (platform theme) | lists restaurants with `is_listed = true`; staff login link. No credentials, no package switcher. |
| `/[slug]` | guest (shop QR) | RSC, menu cached with tag `menu:<restaurant_id>` (max age 60 s) + on-demand revalidation; applies the restaurant's theme | `getMenu(slug)` (anon client, public RLS) |
| `/[slug]/t/[token]` | guest (table QR) | dynamic RSC shell + client `TableProvider`; redirects if the token belongs to another slug | menu via `getMenu` (cached) + `get_table_context(token)` RPC |
| `/m/[slug]`, `/t/[token]` | old links | 308 redirects (next.config / proxy) | see 10-PLATFORM.md |
| `/staff/login` | staff | client form | Supabase Auth |
| `/staff/counter` | counter, admin | client | staff RLS reads + Realtime |
| `/staff/admin/*` | admin | RSC pages + server actions | staff RLS reads/writes |

- If `package = 1` and someone opens a table link, render the plain menu (no action bar) — never an error.
- `/[slug]` for P2/P3 shops still works as a read-only menu (shared on Facebook etc.).
- **Multi-restaurant (2026-10-14):** this section's original single-café routes were replaced; [10-PLATFORM.md](10-PLATFORM.md) is the source of truth for URLs, themes and adding restaurants.
- Locale: `?lang=bn` or cookie `lang` (default `en`). The toggle sets the cookie and re-renders; `<html lang>` follows it.

## Key flows

### Guest opens a table QR (P2/P3)
```
phone ──GET /t/abc123──▶ Next.js RSC
   RSC: getMenu(slug)               (cached)
   RSC: rpc get_table_context('abc123')
        └─ Postgres: find table by qr_token, find non-closed session or create one
           (status 'pending' if require_session_approval else 'open')
   ◀── HTML with menu + {table, session, package, requests}
client TableProvider:
   - stores session_id; if it differs from the stored one → clear cart ("new guests")
   - polls get_session_status(token, session_id) every 5 s while any request is active,
     every 30 s otherwise; pauses when document.hidden
```

### Call Waiter / Place Order / Request Bill
```
client ──rpc call_waiter(token, device_id, items, note)──▶ Postgres (SECURITY DEFINER)
   validate token + package + rate limit
   ensure session
   price_cart(items)  ← prices computed server-side, sold-out check
   insert service_requests (+ request_items) in one transaction
   ◀── {request_id, session_id, duplicate}
Postgres ──Realtime postgres_changes (INSERT/UPDATE service_requests)──▶ Counter board
Counter board: on event → fetch that request with its items → highlight + play sound
```

### Staff updates a request
Counter board updates `service_requests.status` directly (RLS allows staff of that restaurant). A trigger stamps `acknowledged_at` / `done_at` / `handled_by`. Guests see the change on their next poll.

### Admin edits the menu
Server action (zod-validated) → Supabase (staff RLS) → invalidate the menu cache so the public menu updates. `getMenu(slug)` is cached with the tag `menu:<restaurant_id>` and every admin mutation calls `revalidateTag('menu:<restaurant_id>')`. Use whatever tag-cache API the installed Next.js version recommends (`unstable_cache` / `"use cache"` + `cacheTag`); the tag name is the contract.

## Table-session verification (the "is this really from the table?" problem)
- Every table has a secret random `qr_token` (24 hex chars) printed in its QR. Tokens are **not** readable by anon users (no public SELECT on `tables`).
- The first scan creates a session. With `require_session_approval = true` it is `pending` ("scanned, unverified") until staff approve it with one tap (or staff open the table themselves when guests sit down).
- Requests from a `pending` session are accepted but shown on the counter with an **Unverified** badge, so staff can glance at the table before acting.
- Staff **close** the table after payment → next scan starts a fresh session, and the previous guests' devices are reset (cart cleared) because the session id changed.
- If a QR is photographed and abused, admin **regenerates** the token (old printed QR stops working) and reprints.
- Rate limit in Postgres: max 15 requests per session per 10 minutes → `RATE_LIMITED`.

## Realtime (counter board)
- Subscribe on mount to `postgres_changes` for `service_requests` and `table_sessions` with `filter: restaurant_id=eq.<id>`. Realtime respects RLS, so only logged-in staff of that restaurant receive events.
- Event payloads don't include `request_items` → on INSERT/UPDATE fetch the full request (`select *, request_items(*)`).
- On `CHANNEL_ERROR` / `TIMED_OUT` / tab becoming visible again: resubscribe and **refetch all active requests** (never trust the stream alone).
- Sound: browsers block audio until a user gesture → the board starts behind a **Start shift** overlay; the click unlocks an `AudioContext` and requests a **Screen Wake Lock** (re-request on `visibilitychange`). Play a chime on: new request, and on UPDATE where `nudge_count` increased.

## Auth & roles
- Staff accounts are created by the agent/owner in Supabase Auth (no sign-up UI) + a row in `public.staff (user_id, restaurant_id, role)`.
- `middleware.ts` refreshes the session and redirects unauthenticated users from `/staff/(protected)/*` to `/staff/login`. Non-admins hitting `/staff/admin/*` are redirected to `/staff/counter`.
- RLS is the real guard; middleware is UX only.

## Images
- Supabase Storage bucket `menu-images` (public read). Path: `<restaurant_id>/<kind>/<uuid>.webp` (kind = items | offers | brand).
- Admin upload: client-side resize to max 1200 px, convert to WebP (canvas), ≤ 300 KB, then upload.
- Render with `next/image` (`remotePatterns` for the Supabase storage host), fixed aspect ratios (item 1:1, offer 16:9 → 2:1 on phone), `sizes` set correctly.

## i18n
- DB stores `*_en` and `*_bn` columns; UI strings in `src/lib/i18n/{en,bn}.ts` (same keys, type-checked: `bn` must satisfy `typeof en`).
- `pick(row, 'name', locale)` → `row.name_bn ?? row.name_en` (fallback to English when Bangla is missing).
- Numbers/prices: `Intl.NumberFormat(locale === 'bn' ? 'bn-BD' : 'en-BD')` → `৳২৫০` / `৳250`.
- Fonts: Bangla text uses Hind Siliguri via `:lang(bn)` font-family stack.

## Performance budget (guest pages)
- JS on `/m/[slug]` ≤ 150 KB gzipped. Menu is server-rendered; only carousel, sheets, cart are client.
- LCP ≤ 2.5 s (Moto G-class, 4G). First offer image `priority`, others lazy.
- Lighthouse mobile: Performance ≥ 90, Accessibility ≥ 95.
